# Выпуск

Про порядок, а не про возможности.

## Как проверить кандидата

Четыре гейта CI воспроизводятся локально. Гонять их надо **до** пуша и **по
всему дереву**, а не по изменённым файлам: два коммита уже ушли в push
красными именно потому, что линтер запускали по своей правке, а CI запускает
его по `git ls-files`.

Переводы строк — проект ломается на CRLF, bash падает на первой же строке:

```bash
git ls-files -z | xargs -0 grep -lI --binary-files=without-match -P '\r$'
```

Ничего не напечатало — гейт пройден.

Статический разбор по всему дереву, планка `warning`, замечаний должно быть ноль:

```bash
mapfile -t files < <(git ls-files '*.sh'); shellcheck -S warning -e SC1090,SC1091 "${files[@]}"
```

Приёмка целиком, а не отдельный набор:

```bash
bash tests/run.sh
```

Если приёмка идёт на Ubuntu 24.04, наборы со стендами в namespace требуют
разрешения — без него они молча пропускают свою главную часть:

```bash
sudo sysctl -w kernel.apparmor_restrict_unprivileged_userns=0
```

## Как выпускать

1. Прогнать все четыре гейта на том коммите, который станет выпуском.
2. Проставить в CHANGELOG дату у верхней записи.
3. Тег `vX.Y.Z` на тот же коммит.

Правило для правок: изменение, которое нельзя закрыть тестом, краснеющим на
откате, не считается проверенным.

## Общий код с az-awg2

`regen-all`, диагностика, бэкап и восстановление живут в обоих репозиториях
(этот и [az-awg2](https://github.com/blindtechnique/az-awg2)). Исправление в
общем коде обязано попасть в оба и в обоих закрыться тестом — расхождение между
ними не ловится ни одним гейтом.

Ветка `beta` в az-awg2 идёт к 3.0.0 и заморожена: правила заморозки — в
[её RELEASE.md](https://github.com/blindtechnique/az-awg2/blob/beta/RELEASE.md).
Пока она заморожена, изменение общего кода здесь означает изменение и там,
то есть должно проходить по правилам заморозки.
